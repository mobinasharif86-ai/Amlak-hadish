# دفتر املاک — معماری امن (نسخه‌ی جدید)

از این نسخه به بعد، مرورگر کاربر هیچ‌وقت مستقیم به Supabase وصل نمی‌شود و هیچ کلید حساسی داخل کد سایت نیست.
یک Cloudflare Worker (فایل `worker.js`) به‌عنوان واسط امن بین سایت و دیتابیس عمل می‌کند:

مرورگر  →  Worker (این پروژه)  →  Supabase (با کلید محرمانه، فقط سمت سرور)


هر درخواست خواندن/نوشتن داده باید رمز عبور معتبر (مدیر یا مشاور) همراهش باشد؛ Worker قبل از هر کاری این رمز را
در سمت سرور با دیتابیس چک می‌کند. اگر کسی کلید عمومی سایت را هم پیدا کند، به‌تنهایی به هیچ داده‌ای دسترسی ندارد.

## تنظیمات لازم در Cloudflare (فقط یک‌بار)

توی پروژه‌ی خودت در Cloudflare Workers، برو **Settings → Variables and Secrets** (توجه: این جدا از
«Build variables and secrets» است — آن یکی برای زمان build بود و دیگر لازم نیست حذفش کنی، بی‌ضرر است).

دو مقدار زیر را از نوع **Secret** (نه Variable) اضافه کن:

- `SUPABASE_URL` = آدرس پروژه‌ات (مثل `https://xxxx.supabase.co`، بدون `/rest/v1/` در آخرش)
- `SUPABASE_SERVICE_ROLE_KEY` = کلید **service_role** از Supabase → Settings → API

⚠️ کلید service_role را هیچ‌وقت جای دیگری (گیت‌هاب، ایمیل، چت) قرار نده — دسترسی کامل به کل دیتابیس را می‌دهد.
فقط داخل همین بخش Secret در Cloudflare.

بعد از اضافه‌کردن، یک بار دیگر Deploy بزن (یک commit خالی در گیت‌هاب کافی است).

## ساختار فایل‌ها

- `worker.js` — کد سمت سرور؛ رمزها را چک می‌کند و با کلید محرمانه با Supabase صحبت می‌کند.
- `src/` — همان اپ ری‌اکت قبلی، با این تفاوت که به‌جای Supabase مستقیم، با `/api/state` و `/api/public-advisors` (همین Worker) صحبت می‌کند.
- `wrangler.jsonc` — به Cloudflare می‌گوید هم فایل‌های ساخته‌شده (`dist`) را سرو کند، هم `worker.js` را اجرا کند.

## توسعه‌ی محلی

```
npm install
npm run build
```

(اجرای کامل و تست شخصی روی سیستم خودت نیاز به Wrangler dev دارد که در این نسخه پوشش داده نشده — ساده‌ترین راه، تست مستقیم روی نسخه‌ی آنلاین است.)
